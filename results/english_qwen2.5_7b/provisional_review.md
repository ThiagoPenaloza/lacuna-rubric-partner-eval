# Provisional qualitative review of the English local run

The project team wrote this reading after looking at the six raw responses in this folder. It does not replace human adjudication by the participant or the judges. It records where the strict lexical proxy and a human reading agree or disagree. The answer keys, anchors, and patterns in `eval/tasks.json` were written before this run and were not changed after seeing its outputs.

| Task | Team reading | Main failure |
|---|---|---|
| incident_01 | Correct in substance: one combined finding covers the start time, user impact, and recovery action, quotes the context literally, and proposes three separate criteria (C2–C4). | Minor: a single combined finding with the generic reference `context`; a human should confirm that the proposed C2–C4 wording is observable enough. |
| context_02 | Noticed that "useful" is undefined and asked which criteria define a useful summary for the customer. | Chose `review_ready` and `omission` instead of `needs_context` and `insufficient_context`, and suggested defining usefulness instead of first asking for the missing profile or need. |
| ambiguity_03 | Linked the vague word "quickly" to the 2 business day requirement in its question. | The suggestion only says to "clarify the timeframe"; it never writes the verifiable criterion (resolve within 2 business days), and the evidence quotes the context instead of the vague word. |
| feedback_04 | Status and kind are plausible, and the evidence is a literal quote. | Ignored the generic previous feedback in the history and treated C1/C2 as vague; it did not propose tying feedback to textual evidence for each criterion with an absence rule. |
| code_05 | Correct in substance: proposed C1a (valid ISO dates become date objects) and C1b (an explicit error for invalid formats without terminating the process). | Likely proxy false negative: the patterns expect "ISO input produces/returns a date object" and "invalid input returns an explicit error", but the model used a different word order. Needs human adjudication. |
| iteration_06 | Found the remaining deadline and kept the next action the author had already accepted. | Minor: the evidence quotes the accepted C1 instead of the deadline text, and the question asks whether to include a deadline that the context already requires. |

Conclusion: in English the local model passes the content proxy on 2 of 6 tasks, against 0 of 6 in the superseded Portuguese run. The two runs are not directly comparable, because the input language, the prompt language, and the lexical patterns all changed. The remaining failures cluster around the status and kind for insufficient context, the use of history (generic feedback), and turning a vague word into a verifiable criterion. One proxy failure (code_05) looks like a lexical false negative, which is why the proxy is never treated as the final verdict. This table is exploratory team analysis, not an official adjudicated metric.
